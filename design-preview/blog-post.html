Khi mình viết hệ thống đặt lịch lần đầu, mình tưởng chỉ cần một bảng sessions. Ba lần viết lại sau, mình rút ra vài nguyên tắc mà bài này sẽ chia sẻ.

1. Tách slot khỏi session

Slot là thời gian rảnh của mentor, session là cuộc hẹn cụ thể. Gộp hai thứ này làm việc đổi lịch rất khó.

CREATE TABLE availability_slots (
  id UUID PRIMARY KEY,
  mentor_id UUID NOT NULL,
  day_of_week SMALLINT NOT NULL,
  start_time TIME NOT NULL,
  end_time TIME NOT NULL
);
Thiết kế dữ liệu đúng từ đầu rẻ hơn rất nhiều so với sửa khi đã có người dùng.

2. Chống đặt trùng bằng ràng buộc

Đừng chỉ kiểm tra trong code. Hai request cùng lúc vẫn có thể lọt qua. Dùng khoá hoặc ràng buộc loại trừ ở tầng database.
